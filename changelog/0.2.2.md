## App

### New

- **Runs start from the work itself.** A long, structured brief — phases, priorities, a definition of done — now opens a ULW run with goals and the DAG pane on its own. No `/ulw` prefix and no closing `mass ulw` needed; explicit orders keep working exactly as before.
- **A closing `mass ulw` is a run order too.** Ending a message with the directive starts the same native run with the message text as the brief.

### Improvements

- **Dispatch goes through real workers.** A run's dispatch step records each goal against the worker session that actually runs it, so a run advances past plan creation instead of stalling there with goals and no workers.
- **Packaged installs find their engine.** The app ships its run companions beside the service bundle, so a clean install probes the engine healthy with no bun and no checkout on the machine.
- **Publishing is gated.** Releases now build, type-check, lint and test on the tag path before anything ships, so an installer can no longer go out untested.

### Fixes

- **The DAG tells the truth.** Failed and cancelled children keep their state and are counted, and a parent whose children all failed no longer reports completed.
- **The code graph stays usable mid-build.** Queries are bounded, a stale generation stays readable while the next build runs, and the panel restores only when the index is ready.
- **Short chats stay chats.** Pasted logs, read-only briefs and one-line asks never trigger a run — only a long brief that orders the work does.
