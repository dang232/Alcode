# OpenCode-server

Alcode gebruikt een OpenCode-server. Standaard start het die voor u; u hoeft daar niets voor te doen. Deze pagina is bedoeld voor wie een bestaande server wil gebruiken of de automatisch gestarte server wil beheren.

## Hoe Alcode een server vindt

Bij het starten zoekt Alcode in deze volgorde:

1. Een server hergebruiken die het zelf al heeft gestart.
2. Verbinding maken met een externe server, als u die hebt ingesteld zoals hieronder beschreven.
3. Een server op de standaardpoort `4096` automatisch herkennen.
4. Anders zelf een server starten en beheren.

Als er niets is ingesteld, gebeurt stap 4 automatisch en kunt u aan het werk.

## Een bestaande server gebruiken

Stel het volgende in voordat u Alcode start:

```bash
OPENCODE_HOST=http://localhost:4096 OPENCODE_SKIP_START=true alcode
```

- `OPENCODE_HOST` is het volledige adres van uw OpenCode-server, inclusief de poort, bijvoorbeeld `http://localhost:4096`. Er mag geen pad achter staan.
- `OPENCODE_SKIP_START=true` voorkomt dat Alcode zelf een server start.

Wilt u alleen de poort wijzigen? Gebruik dan `OPENCODE_PORT` in plaats van `OPENCODE_HOST`.

Als de poort in `OPENCODE_HOST` ontbreekt of het adres een pad bevat, negeert Alcode die waarde en start het zelf een server. Controleer bij een onverwachte verbinding de opstartlogs op een waarschuwing met `[config]`.

## De server beheren via de CLI

```bash
alcode status
alcode logs
alcode restart
alcode stop
```

Met alleen `alcode` start de server op de achtergrond. Voeg `--foreground` toe om hem aan uw terminal gekoppeld te houden.

## Alcode starten bij het aanmelden

Met `startup enable` installeert u een gebruikersservice van het besturingssysteem. Alcode gebruikt `launchd` op macOS, `systemd --user` op Linux en Taakplanner op Windows.

```bash
alcode startup enable
alcode startup status
alcode startup disable
```

Stel bij het inschakelen van de service een wachtwoord in om de interface te beschermen:

```bash
ALCODE_UI_PASSWORD='secret' alcode startup enable
```

Voor een server zonder webinterface die bij het aanmelden start en desktop- of mobiele clients bedient, voegt u `--api-only` en een bereikbaar hostadres toe:

```bash
alcode startup enable --port 3000 --api-only --host 0.0.0.0 --ui-password secret
```

`startup enable` neemt een momentopname van uw huidige omgevingsvariabelen over in de service. Daardoor gedraagt die zich meer alsof u `alcode` vanuit dezelfde shell start. Providertokens, `PATH`, SSH-agentinstellingen en andere CLI-variabelen voor authenticatie en configuratie blijven beschikbaar. Gebruik `--no-env-snapshot` voor een minimale serviceomgeving.

De opstartservice onthoudt `--port`, `--host`, `--ui-password` en `--api-only`. Herstarts via de CLI en na updates gebruiken deze opgeslagen instellingen opnieuw.

Maak zo een verbindingslink voor een andere Alcode-app:

```bash
alcode connect-url --port 3000 --server http://your-host:3000 --qr
```

Met `alcode connect-url --help` ziet u alle linkopties, waaronder `--name`, `--lan`, `--server`, `--api-only`, `--ui-password` en `--qr`.

U kunt tunnels voor de draaiende service afzonderlijk blijven beheren:

```bash
alcode tunnel start --port 3000
alcode tunnel stop --port 3000
```

Een tunnel stoppen herstart de service of de app niet.

## 'OpenCode wordt opnieuw gestart'

Tijdens het starten of herstarten toont Alcode dat OpenCode opnieuw wordt gestart. Verzoeken wachten totdat de server klaar is. Direct na het openen of herstarten is dat normaal. Blijft deze melding staan? Zie [Verbinding met OpenCode](/nl/troubleshooting/opencode-connection/).
