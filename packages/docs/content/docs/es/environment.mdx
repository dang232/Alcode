# Variables de entorno

Alcode lee estas variables al arrancar. Para servicios de inicio, `alcode startup enable` guarda por defecto una copia del entorno actual, así que vuelve a ejecutarlo después de cambiar variables que quieras usar en el servicio.

## Variables para OpenCode, Git y la terminal

Para darles a OpenCode, a Git, a la terminal y a las [acciones de proyecto](/es/project-actions/) variables propias, como un token de API o la dirección de una base de datos, añádelas en **Configuración → General → Variables de entorno** en lugar de exportarlas antes de arrancar Alcode. Los valores se quedan en la máquina donde se ejecuta Alcode, en `environment.json` dentro del directorio de datos, y solo tu usuario puede leerlos. Configuración nunca vuelve a mostrar un valor: puedes sustituirlo o quitarlo, pero no leerlo.

- OpenCode las recibe al arrancar, así que reinícialo después de un cambio. Configuración ofrece el botón para hacerlo.
- Las variables que defines con `opencode service set env` también llegan a OpenCode. Las de Configuración tienen prioridad.
- Git, la terminal y las acciones de proyecto las reciben la próxima vez que se ejecutan.
- Las variables que Alcode define para el propio OpenCode, como su contraseña y su configuración, tienen prioridad sobre las tuyas.

Un proyecto puede añadir sus propias variables, o un comando que las imprima como `direnv export json`, en **Configuración → Proyectos**. Consulta [Proyectos](/es/projects/#entorno-del-proyecto).

Las variables no llegan a un servidor de OpenCode que hayas arrancado tú, y la extensión de VS Code no tiene este ajuste. Todo lo que sigue lo lee el propio Alcode al arrancar.

## Servidor Alcode

### `ALCODE_HOST`

Dirección donde escucha el servidor web de Alcode. Usa `0.0.0.0` para permitir acceso desde otras máquinas.

### `ALCODE_LAN_URL`

La dirección con la que otros dispositivos de tu red llegan a Alcode, por ejemplo `http://192.168.1.20:3000`. Los enlaces y códigos QR de emparejamiento la ofrecen en lugar de la que Alcode detecta por sí mismo. Defínela cuando esa detección falle, por ejemplo en Docker, donde Alcode solo ve la dirección interna del contenedor.

### `ALCODE_UI_PASSWORD`

Contraseña para la interfaz del navegador. Úsala cuando no te limites a localhost, o cuando uses túneles o un proxy inverso.

### `ALCODE_UI_SESSION_TTL_HOURS`

Cuánto dura un inicio de sesión en el navegador, en horas, cuando «confiar en este dispositivo» está desactivado. El valor por defecto es `12`.

### `ALCODE_UI_TRUSTED_SESSION_TTL_DAYS`

Cuánto dura un inicio de sesión, en días, en un dispositivo marcado como de confianza. El valor por defecto es `7`.

### `ALCODE_API_ONLY`

Inicia Alcode en modo headless cuando vale `true` o `1`. Las rutas API siguen disponibles para clientes de escritorio y móviles, pero no se sirve la UI del navegador.

### `ALCODE_FRAME_ANCESTORS`

Orígenes que pueden mostrar Alcode dentro de un frame en su propia página, separados por espacios, por ejemplo `https://dash.example.com`. `*` permite cualquier sitio. Por defecto solo Alcode y sus apps de escritorio y móvil pueden incrustarlo, para que ningún otro sitio pueda superponer sus botones.

### `ALCODE_DATA_DIR`

Cambia el directorio de datos de Alcode. Por defecto es `~/.config/alcode`.

### `ALCODE_CHATS_DIR`

Cambia la ubicación de los directorios de chat gestionados que Alcode crea para chats sin proyecto. Por defecto es `~/.config/alcode/chats`. Indica un directorio que el servidor OpenCode pueda leer cuando Alcode y OpenCode se ejecutan con usuarios distintos. Los chats existentes no se mueven.

### `ALCODE_COMPRESS_API`

Controla la compresión de respuestas de la API. `true` o `1` la activa; `false` o `0` la desactiva.

### `ALCODE_SKIP_API_COMPRESSION`

Desactiva la compresión de respuestas de la API si vale `true` o `1`. Tiene prioridad sobre `ALCODE_COMPRESS_API`.

### `ALCODE_VERBOSE_REQUEST_LOGS`

Activa logs HTTP detallados si vale `true` o `1`.

### `ALCODE_UPDATE_API_URL`

Cambia el endpoint de comprobación de actualizaciones. La mayoría de usuarios no debería tocarlo.

### `ALCODE_PACKAGE_MANAGER`

Fuerza el gestor de paquetes usado para actualizar cuando la detección automática se equivoca.

## Proxy

### `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`

Envía a través de un proxy las solicitudes salientes propias de Alcode, como los límites de uso y los catálogos de skills. También funcionan los nombres en minúsculas. Los hosts de `NO_PROXY` se conectan directamente, y `localhost`, `127.0.0.1` y `::1` siempre lo hacen, así que las devoluciones de inicio de sesión y el servidor local de OpenCode siguen funcionando.

## Servidor OpenCode

### `OPENCODE_HOST`

Conecta Alcode a un servidor OpenCode existente. Debe ser un origin `http` o `https` con puerto explícito y sin ruta, query ni hash. `OPENCODE_HOST` tiene prioridad sobre `OPENCODE_PORT`.

### `OPENCODE_PORT`

Define el puerto del servidor OpenCode. Con OpenCode gestionado pide ese puerto; con `OPENCODE_SKIP_START=true` conecta a un servidor externo en ese puerto.

### `OPENCODE_SKIP_START`

Evita que Alcode arranque su propio servidor OpenCode cuando vale `true`.

### `ALCODE_OPENCODE_HOSTNAME`

Hostname para el servidor OpenCode gestionado por Alcode. Por defecto es `127.0.0.1`.

### `OPENCODE_BINARY`

Ruta al ejecutable `opencode` que debe usar Alcode.

### `OPENCODE_CONFIG`

Ruta a un archivo de configuración concreto de OpenCode.

### `OPENCODE_CONFIG_DIR`

Ruta al directorio de configuración de OpenCode para agents, skills, snippets y descubrimiento de config.

### `OPENCODE_DATA_DIR`

Directorio de datos personalizado para el servidor OpenCode gestionado.

### `OPENCODE_WSL_DISTRO`

Elige la distro WSL usada para la integración con OpenCode en Windows.

### `ALCODE_OPENCODE_WSL_DISTRO`

Alias específico de Alcode para elegir la distro WSL. `OPENCODE_WSL_DISTRO` tiene prioridad si ambas están definidas.

### `OPENCODE_JWT_SECRET`

Secreto para firmar tokens de autenticación de la UI. En servicios persistentes, usa un valor largo y aleatorio.

## Terminal y Git

### `ALCODE_TERMINAL_SHELL`

Ejecutable de shell para las sesiones de terminal en Alcode.

### `ALCODE_GIT_BINARY`

Ejecutable de Git usado por las funciones Git de Alcode.

### `GIT_BINARY`

Override alternativo para el ejecutable de Git. Para ajustes específicos de Alcode, prefiere `ALCODE_GIT_BINARY`.

### `ALCODE_GIT_READ_CACHE_TTL_MS`

TTL, en milisegundos, para lecturas de archivos con cache respaldadas por Git. Usa `0` para desactivar la cache al depurar.

## Voz y túneles

### `OPENAI_API_KEY`

API key que usan las funciones de voz de Alcode cuando llaman a OpenAI directamente. Nunca se envía a un servidor propio compatible con OpenAI: dale a ese servidor su propia clave en Ajustes.

### `ALCODE_ALLOW_REMOTE_OPENAI_COMPAT_URLS`

Permite base URLs remotas compatibles con OpenAI para funciones de voz cuando vale `true` o `1`.

### `NGROK_AUTHTOKEN`

Token de autenticación de ngrok usado por los comandos de túnel de Alcode. También puedes configurarlo con `ngrok config add-authtoken <token>`.

## Ayudas de runtime

### `BUN_BINARY`

Ejecutable de Bun que Alcode debe usar al iniciar procesos daemon.

### `BUN_INSTALL`

Raíz de instalación de Bun. Alcode la usa para encontrar `bin/bun` al iniciar daemons y actualizar.

### `VITE_OPENCODE_URL`

API base URL de build-time para la web app construida con Vite. La mayoría de usuarios no debería usarla en CLI o desktop normales.
